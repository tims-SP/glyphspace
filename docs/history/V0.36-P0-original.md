# 字间 · V0.36 字根系统重构任务规划与验收标准

> 版本：规划草案 V0.36-P0  
> 基线文件：`index.html`（V0.35，约 230 KB）；`字间_V0.35_字根问题总清单与验收规范.md`；用户提供的 2008 年新世纪五笔简体字根键位图。  
> 本文为实施计划，不代表任务已完成或任何字形已通过原图认证。

## 1. 总目标与范围

**总目标：** 在不改变原生 HTML/CSS/JavaScript、单 HTML 离线交付、五笔取码状态机以及 V0.34 全屏布局的前提下，建立可追溯的 2008 参考图可视形态资产库和局部固定坐标系统；补齐缺项、统一绘制、逐形态校准，让键盘三种视图共享唯一真实数据。

将四件事分开验收：

1. **覆盖率**：参考图有的可辨形态，资产库是否都有；与现有 151 个实例数量无关。
2. **语义准确性**：是正式根、变体、圈注、补码标注还是口诀关联；是否影响五笔取码。
3. **视觉准确性**：Path、颜色/视觉重量、位置、尺寸、光学偏移是否对得上参考图。
4. **技术稳定性**：缩放/高亮/新增条目/迁移/跨端输入后是否发生非预期变化。

### 不在本轮范围

- 不替换前端框架，不拆分正式交付文件，不引入线上字体、JS/CSS CDN 或其他运行时网络依赖。
- 不扩充 176 个练习字、不修改键名/成字字根取码/识别码/补码规则。
- 不进行新一轮主页面信息架构设计；除焦点字根放大等必要可辨性补救外不增加功能。
- 不把参考图裁片或图片像素用于键帽正式渲染。图像仅作为独立校准工作台的对照素材。

## 2. 基线事实与主要风险

- V0.35 数据模型采用 `ROOTS[key]` 字符数组及平行的 `ROOT_COORDS[key][index] = [x,y,size]`；两个数组依靠位置匹配。
- 当前 `ROOTS` 包含 156 条，剔除 5 条仅作口诀关联的隐藏形态，**键盘上可视实例为 151**；不意味着参考图总数为 151。
- `KEY-root-index` 虽作为审计 ID，却依赖当前数组次序，不能视为跨增删操作的永久 ID。
- 有 `humanReviews`、参考图裁切、坐标 localStorage 迁移，但相关 key/signature 仍与索引或局部信息绑定，Path 更改未完整纳入复核过期判定。
- 参考图 **M 键冂右侧多个小框构形明确未独立登记**；Q、I、K、L 等为高风险，具体新增数不能在逐图编号前推断。
- 既有模拟测试 20/20 证明有限回归集通过，**不证明 151 项均准确、无漏项或真机合格**。

## 3. 冻结的系统架构

### 3.1 布局体系

| 层 | 技术 | 唯一职责 |
|---|---|---|
| 主界面 | CSS Grid/Flexbox | 全屏三大区域、紧凑响应式、零滚动 |
| 键盘排列 | CSS Grid 或等效稳定行布局 | 按标准 QWERTY 排列键帽，不管理字根 |
| 单个键帽 | SVG `viewBox="0 0 100 100"` | 字根及注释的唯一局部坐标空间 |
| 轮廓资产 | SVG `<symbol>` / `<path>` / `<use>` | 可独立引用、无字体回退的字形 |
| 实例几何 | `{x,y,width,height,anchor,ox,oy}` | 相对原图的规范化矩形与光学补偿 |
| 交互状态 | 保留统一输入状态机 | 根据 `instanceId` 高亮实例，不重排基础几何 |
| 放大视图 | 共享实例与符号引用 | 辅助可读性；不维护第二套坐标 |

`100 × 100` 是**键帽内部虚拟坐标系**，不是浏览器绝对像素。键帽外部自适应缩放；根形在任何屏幕的归一化坐标保持恒定。原图的不同分区键帽排版不强行照搬；只移植每键内部空间关系。

### 3.2 唯一数据实体

- `ReferenceShape`：参考图中的每个可辨视觉形态。含 `referenceShapeId`、键位、原图裁框或标注、原图版本 SHA-256、辨认置信/难点。
- `GlyphAsset`：原始 SVG 路径、`viewBox`、实际笔画边界 `inkBBox`、字形来源、字形 SHA-256/版本、许可证。
- `GlyphInstance`：永久 `instanceId`、`referenceShapeId`、`assetId`、键位、类别、关联正式字根、几何、层级。
- `KeyMeta`：键盘物理排列、区位编号、字母、笔画区域标注锚点等。
- `Review`：存在性、轮廓、位置、比例、语义五维结论，证据、资产/参考图/几何签名和状态。
- `UserOverride`：以 `instanceId` 存储用户几何修正，不覆盖经过发布认证的默认几何。

建议示意（非实测）：

```json
{
  "instanceId": "M-frame-variant-02",
  "referenceShapeId": "2008-M-shape-07",
  "key": "M",
  "category": "variant",
  "semanticRootId": "M-lower-frame",
  "assetId": "svg-m-frame-02",
  "geometry": { "x": 58, "y": 70, "width": 11, "height": 14, "anchor": "ink-center", "ox": 0, "oy": 0 },
  "reviewStatus": "pending"
}
```

禁止从数组索引、显示字符或码位推导新 ID；同一 SVG asset 可以被多个实例引用，每个原图视觉实例必须可独立选择、移动、复核。复合部件可以是一个语义实例内的多个 Path。圈注与补码框独立分类，不能误记作输入字根。

## 5. 分阶段验收门槛

### Gate A — 数据与迁移（T00–T04）

- 151 个旧可视实例都生成且能验证永久 ID（旧 ID 映射无歧义）；五条关联项不误映射为编码根。
- 新增、移除、排序一个实例后其他 `instanceId` 和坐标原样保持。
- 所有有效旧版用户坐标逐项迁移并通过前后对比；不明来源记录隔离，绝不静默覆盖。
- 底层取码状态机、15 种识别码及 PY/PU/QT 补码保持原结果。

### Gate B — 原图完整性（T01、T05）

- 25/25 正式键位已经逐个清点；原图可辨总数**由清点结果生成**，不得预设为 151 或其他数量。
- 所有可辨视觉形态具有唯一 `referenceShapeId`；确认缺失=0，错误类别=0，未登记对象=0。
- 原图不可辨项独立列表注明位置、清晰度限制和处理决定；不得偷偷当成“已认证”。
- 字根、变体、关联语义、圈注和补码第二键严格区分。

### Gate C — 几何与视觉（T03、T06、T07、T08）

- 规范化坐标变换在桌面/手机全视图一致；基础位置改变仅影响被操作实例。
- 建议主根参考阈值：归一化中心偏差不超过 **3/100**，宽高偏差不超过 **10%**；难辨微小图形允许经人工签字的可追溯例外。
- 所有新形态完成形状、存在、位置、比例、语义五维复核，未审核不得进入“已完成”统计。
- 无未批准的字根↔字根、字根↔字母、字根↔数字、字根↔圈注碰撞；所有碰撞白名单有理由。
- 高亮不改变标准几何，必要的明显放大移到单键或辅助视图；不覆盖邻居。
- Path、默认几何、原图版本改变时相关人工复核自动失效。

### Gate D — 程序回归（T09–T11）

- 自动比较旧版 176 字所有已存在的编码序列；变化必须有明确 bug 修复证明及人工审批，否则阻断发布。
- 覆盖 15 类末笔识别码、3 类补码、成字字根、键名字、盲打遮蔽、重复键和错误输入不推进。
- 练习页常规视口无纵横滚动，迷你键盘不横滚，聚焦字根不受遮挡。
- 断网和 `file://` 打开仍可完整练习，无外部字体文件和 CDN。
- 浏览器模拟尺寸至少：320×568、375×667、390×844、430×932、844×390、1024×768、1440×900、1920×1080；DPR 1/2/3，页面和键盘折叠/展开均检查。
- Android Chrome、iOS Safari 的真机验收单必须保留独立结果；无实机时仅可标为“待实机”，不能冒称通过。

## 8. 风险与决策

1. **低分辨率原图**：一些微型构形可能无法从当前 JPEG 可靠区分；记录“不确定”，如有高清合法来源再复核，禁止凭口诀虚构轮廓。
2. **相同形态重复出现**：语义上可以复用一个 SVG Asset，视觉实例必须保留各自位置和 ID。
3. **字根在 35px 手机键帽里过小**：不通过破坏布局位置来增大全部字根，而是在单键/焦点辅助区域解决辨识；需要真机检验。
4. **校准数据兼容性**：先构建不可变 V0.35 索引到稳定 ID 的对应表，再允许向中间插入形态；任何冲突都要隔离和提示。
5. **许可证及参考图使用**：不得把 2008 原图的位图混入最终键盘；保留 Noto/KanjiVG 等 SVG 提取来源、许可证和变更记录。
