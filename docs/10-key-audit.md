## 每键必须新增的事实字段

* `reference_source_sha256`、25键框、`referenceShapeId`、是否父区域/圈注/空白误框。
* 原图独立可辨形态数、与永久ID对应数、**经证实的缺失数**、无法辨认数；若不能判断，字段保持 `null`，禁止填0或把36条旧未匹配当缺根。
* 实例类别：正式根、变体、注释、补码、关联；五维复核：existence / outline / position / scale / classification。
* 核验的轮廓资产SHA、局部坐标、真实`inkBBox`、几何复核签名、审阅者与证据。
* 25键全覆盖、冲突排他性、回滚/过期记录。

## 现有冲突与审阅排序

* **M键**：旧审计已识别冂右侧微型框、贝旁微型构形未独立建模。应优先从原图确认身份再补画，不能因候选数量自动补根。
* **Q、I、K、L、O、N、B、V等**：历史风险为潜在高密度微形遗漏，未认证前都属于调查线索。
* **K:2川 / K:3丨**：第46轮把两条共享`2008-K-vis-03`的错误候选资格同时隔离；没有判定哪条身份正确。
* **E:1舟 / E:8用**：引用同一个已否定的空白误框，不能恢复。
* **B:7孑 / V:4巛**：跨轮候选命名空间冲突仍需解决；另有七项微形待逐笔。
* 来源数字的不同层级不能混算：第46轮审计分类 **139条仅供审阅、2条新阻断、8条旧否定、2条命名空间冲突、5条关联 = 156条**；其中151条可视。

[原始25键台账CSV](./tasks/25-key-audit.csv)提供机器可读、默认未审核的空字段。表内`confirmedMissingCount`空值与“确认缺失数为0”不是一回事。

## 完整性验收定义

每个可辨参考形态具有可追溯证据及类型；25/25键逐笔复核、所有可辨形态对应到独立视觉实例或已记录的不可辨例外；正式根/变体/圈注/口诀与补码必须分开；不得采用裁片像素重叠、字体字形或旧SVG作为来源认证。具体闸门见[07验收](./07-acceptance.md)。
