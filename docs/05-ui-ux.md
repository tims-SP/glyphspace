# 05 · 界面与交互规格

> **编号约束**：本文描述独立的**UI-01–UI-05轨道**；不得将第36–40轮原型旧文件所称“T03/T05”误认为原始字根T03 SVG坐标内核/T05完整性补图。参见[14 UI编号调和](./14-ui-change-control.md)和[原始T00–T11](./history/V0.36-P0-original.md)。

> **状态**：目标规范 + 现有基线观察 + 隔离原型经验；非正式V0.36成品截图说明。

## 体验层次

1. **练习焦点**：当前汉字、输入位置、上一输入是否正确。
2. **拆分步骤**：当前字根/笔画、五笔编码和必要提示。
3. **键盘**：当前键高亮、其他键弱化、物理位置稳定。
4. **辅助层**：完整字根查阅、校准、设置、帮助，平时收起。

强调应遵守当前操作顺序，不依赖单一颜色表达正确/错误，避免高亮过度竞争注意力。

## 桌面端目标

- 目标字和输入位占据最清晰区域；辅助信息紧邻，键盘稳定处于同一视野。
- 完整25键可见，字根只在聚焦处强调，非聚焦内容保持最低可辨性。
- 设置、人工校准、扩展图谱等不应占用核心训练常驻高度。
- 页面本体不滚动；缩放较高、窗口极矮时优先折叠二级内容，并始终保留输入控件。

## 移动端目标

- 键帽首要显示字母；**不把所有字根强缩进每个键帽**。
- 聚焦键的字根进入独立放大区，支持按键切换和分页；第36轮原型每页6项。
- 软键盘弹出时练习目标/输入反馈/当前步骤不能被压到屏幕外。
- 收起屏幕键盘后，辅助栏仍提供当前汉字拆字对应的迷你键盘。
- 支持安全区、横屏、窄屏、大字体；整体不滚动原则不能破坏可触达性。

## 状态交互（目标）

```text
start → prompting → typing → correct/incorrect → next
                       ↓
            key-focused / root-focused
                       ↓
  keyboard-expanded ↔ keyboard-collapsed
                       ↓
     modal/help/settings (焦点管理)
```

重点边界：聚焦键、聚焦字根、拆字步骤、提示层的状态须由同一个上游训练状态推导。快速连续键入、退格、键盘折叠/展开和对话框关闭不能造成高亮错乱。

## 键盘布局

- 视觉行：`QWERTYUIOP`、`ASDFGHJKL`、`ZXCVBNM`。
- 五笔25键：`QWERTYUIOPASDFGHJKLXCVBNM`（用于字根映射，不包含Z）。
- 其他字符键与系统输入按钮为输入控制而非新增字根键位。
- 焦点切换动效需短促、可降低；动画不能影响焦点与笔画清晰度。

## 无障碍与真实验证

- 键位有稳定名称、焦点可见、`aria-pressed`/`aria-current` 等状态与可见状态一致（按组件语义选择合适属性）。
- 弹层打开时管理焦点，关闭时恢复正确控件；键位与分页支持无鼠标操作。
- 即时反馈通过不打断输入的状态区提供，避免过多语音播报。
- 依据WCAG原则检查对比度和缩放，但**最终验收要由实际屏幕阅读器完成**。
- 隔离原型曾有Chromium桌面/手机测试，不等于VoiceOver/TalkBack/NVDA实测通过。

## 响应式验收矩阵（拟订）

| 场景 | 必须观察 |
|---|---|
| 桌面宽窗与窄窗 | 不横向溢出、聚焦区和键盘同屏 |
| 手机竖屏/横屏 | 不丢键、分页可达、文字可读 |
| 移动软键盘打开 | 当前汉字/输入反馈可见；可以继续提交输入 |
| 200%浏览器缩放 | 可发现全部主操作，内容不不可达 |
| 键盘折叠、切换焦点、退格 | 高亮同步且焦点连续 |
| 操作系统增大字体、减少动态效果 | 训练仍可用 |

零滚动不是单个视口截图中 `scrollHeight=clientHeight` 就算通过；必须同时满足键盘/读屏对所有操作的可达性。
